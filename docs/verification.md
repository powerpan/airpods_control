# 採集基礎驗證記錄

這份記錄區分自動化檢查、真實設備觀察和未完成的驗收，不代表長期可靠性或特定硬件組合的認證。

## 構建與自動化檢查

- 原生 macOS Debug 應用通過 `script/build_and_run.sh` 編譯、啓動及進程檢查；ad-hoc 簽名驗證通過。
- 配置文件 plist/pbxproj 通過語法檢查；實際應用包包含運動權限用途聲明。
- 採集基礎階段的 31 項測試通過：14 個 MotionCore、17 個 MotionRuntime。後續新增功能的測試結果見 [功能驗收記錄](features-acceptance.md)。
- 構建日誌僅保留在被 Git 忽略的 `build/`，不作為公開文檔的一部分。

## 真實採集觀察

使用真實耳機數據源檢查了以下行為；模擬源的結果沒有混入設備觀察。

| 檢查 | 觀察結果 |
| --- | --- |
| 權限與連接 | 已授權、已連接及數據可用狀態分別顯示 |
| 實時字段 | Euler、四元數、三軸角速度、用戶加速度、重力和採樣時間戳持續更新 |
| 更新頻率 | 頻率由實際採樣時間戳計算；不作為固定頻率承諾 |
| 校準 | 設置參考後顯示相對姿態，後續隨動作變化；未使用外部姿態真值，不作精度結論 |
| 暫停顯示 | 姿態、向量、時間戳及曲線凍結，收幀計數和狀態繼續更新 |
| 停止 | 顯示已停止、隱藏實時頻率、禁用校準，並保留註明非實時的最後一幀 |

曾發現舊式 Core Motion 回調在 Swift 6 下被推斷為主 actor，後台隊列觸發執行器斷言。生產回調現由 `nonisolated` 工廠創建為 `@Sendable` 閉包，並有從主 actor 創建、在 `Task.detached` 或 `OperationQueue` 調用的回歸測試。

明確斷連、資料來源重啟或超出恢復期限時不會沿用舊參考姿態；同一資料流在恢復期限內恢復的處理規則見 README。連續性計數也包含短暫停滯恢復和主動停止等事件，不能直接解釋為藍牙掉線次數。

## 軟件與模擬驗證

- 四元數非交換校準順序、任意參考姿態歸零、`q/-q` 等價、±180°跨越及 Euler 奇點重建。
- 不規則採樣頻率、時間窗、異常數值與時間戳拒絕、按實際時間間隔平滑。
- 假源驗證重複及併發啓停、無數據超時、斷連及流結束恢復、權限拒絕與撤回、等待授權、訂閱背壓、關閉釋放和計數隔離。
- 原生模擬模式可啓動，數值、曲線和按鈕可操作；模擬頻率不能用於推斷真實耳機頻率。

## 仍需確認

- 不同兼容耳機、系統與固件組合。
- 斷開、放回充電盒、重新佩戴與重連的完整步驟。
- 系統睡眠喚醒、長時間運行及音頻設備自動切換。
- 實際動作軸、符號、精度、漂移與延遲；需要外部姿態真值才能作計量結論。
- 最低部署版本的實際運行。
